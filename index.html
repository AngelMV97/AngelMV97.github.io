01

JUNKY ALCHEMIST

Junky Alchemist is a first-person potion-making game developed for a Game Jam, where the player must prepare randomized recipes under time pressure while managing limited psychoactive substances that temporarily affect movement, perception, and gameplay flow.

My Responsibilities

  • Implemented the substance system with player movement, visual effects, inventory counters, and game-over logic.
  • Built and connected the complete UI flow: main menu, HUD, order panel, warning screen, game-over screen, and win screen.
  • Migrated and unified features from separate prototype scenes into the final SampleScene.
  • Debugged scene merge issues, missing script references, duplicated systems, prefab configuration problems, and Unity UI asset setup.

Technologies: Unity, C#, Unity UI, Input System

01

JUNKY ALCHEMIST

Main Challenges & Solutions

One of the biggest challenges was merging different gameplay systems created in separate scenes. Player movement, potion mechanics, UI, and substance effects originally worked independently.

I reorganized the project around a single final scene and carefully connected each system without breaking existing functionality. The GameManager became responsible for coordinating the menu, HUD, orders, timer, and general game state.

I also resolved UI integration problems, including missing script references, non-interactive menus, incorrect sprite import settings, HUD counters that did not update, and order panels appearing at the wrong moment.

These issues were solved by cleaning serialized references, using prefab-based UI elements, and centralizing gameplay and interface coordination through the GameManager.

What I Learned

  • Scene and system integration
  • Gameplay-loop architecture
  • Unity UI coordination
  • Prefab and serialized-reference debugging
  • Collaborative Game Jam development

WOBBLEHEADS

A team-developed 3D multiplayer party game created during a Game Jam using Unity and Blender.

Players launch insults as projectiles that progressively enlarge their opponents' heads. As the heads grow, movement and positioning become increasingly difficult until the head eventually bursts.

Key Features

  • Local multiplayer arena gameplay
  • Projectile mechanic that progressively enlarges opponents' heads
  • Movement affected by dynamically changing character balance
  • Physics-inspired gameplay and environmental hazards
  • Stylized low-poly urban environment

Technologies: Unity, C#, Blender

02

WOBBLEHEADS

Main Challenges & Solutions

The game required the arena, characters, projectiles, and environmental hazards to remain readable from an isometric multiplayer camera, even when several actions occurred at the same time.

The team used simplified silhouettes, distinct colors, clear platform boundaries, and controlled prop density to preserve visual clarity during fast gameplay.

Another challenge was coordinating game systems and assets produced simultaneously by different team members under Game Jam time constraints. Modular assets, clear task ownership, and frequent integration tests helped maintain a cohesive playable build.

What I Learned

  • Game Jam production workflow
  • Multidisciplinary teamwork
  • Gameplay readability
  • Rapid iteration and integration
  • Unity and Blender collaboration

3D ENVIRONMENT DESIGN

Designed, modeled, and optimized the complete playable environment for Wobbleheads as part of a multidisciplinary Game Jam team.

My contribution covered the complete environment-production pipeline, from blockout and level layout to modular asset creation, material setup, optimization, and Unity integration.

Responsibilities

  • Designed the complete gameplay arena layout
  • Modeled the environment using a modular low-poly workflow
  • Created reusable buildings, trees, sidewalks, barriers, and urban props
  • Reduced the environment from approximately 61k to fewer than 19k triangles
  • Prepared assets and materials for Unity integration

Technologies: Blender, Unity, Low-poly Modeling, Modular Design

03

3D ENVIRONMENT DESIGN

Main Challenges & Solutions

The initial scene contained approximately 61,000 triangles, which was excessive for the intended Game Jam scope and could negatively affect runtime performance.

I simplified hidden geometry, removed unnecessary subdivisions, reused modular components, and optimized individual props. This reduced the final scene to fewer than 19,000 triangles while preserving its visual quality.

Another challenge involved maintaining gameplay readability from an isometric camera. Tall structures and dense decoration could obscure characters or movement areas.

I adjusted building height, prop density, silhouette contrast, and road spacing so the environment remained visually appealing without interfering with gameplay.

What I Learned

  • Low-poly scene optimization
  • Modular asset production
  • Gameplay-oriented level composition
  • Blender-to-Unity export workflow
  • Isometric-camera readability

CATTLE HERDING

Custom gameplay implementation created with assets from Unity Learn's Basic Gameplay mission.

I developed an original two-player cattle herding mechanic in which players compete to guide wandering animals into a corral by launching herding dogs.

Key Features

  • Two-player local multiplayer using Unity's Input System
  • Dynamic animal spawning and tracking
  • Collision-based animal behavior with cooldown protection
  • Random corral spawning with distance constraints
  • Real-time UI and centralized game state

Technologies: Unity, C#, Input System, Unity UI

04

CATTLE HERDING

Main Challenges & Solutions

Animals initially registered several collisions in rapid succession, causing repeated rotations and unpredictable movement.

I added a cooldown state after each valid collision, temporarily preventing additional rotations and creating more stable behavior.

The win condition also needed to consider both dynamically spawned animals and cattle already placed in the scene.

I centralized animal tracking in the GameManager, allowing the game to monitor the complete population, update the UI, and detect when all animals had entered the corral.

What I Learned

  • Local multiplayer input
  • Collision-state control
  • Dynamic spawning
  • Singleton-based game managers
  • Real-time UI updates

PLANE PROGRAMMING

Extended the original Unity Learn challenge by implementing custom flight-control, collectible, UI, physics, and game-state systems.

The player pilots an aircraft through an obstacle course while maintaining controlled flight and collecting items.

Key Features

  • Aircraft movement using Unity's Input System
  • Automatic pitch stabilization
  • Physics-based crash behavior using torque
  • Collectible system
  • Game Over UI and centralized game-state management

Technologies: Unity 6, C#, Rigidbody Physics, Input System

05

PLANE PROGRAMMING

Main Challenges & Solutions

When the player released the controls, the aircraft remained at its previous pitch, making flight difficult to recover and reducing control precision.

I implemented gradual interpolation toward a neutral pitch whenever no vertical input was detected. This preserved responsiveness while improving flight control.

The original collision response also stopped the game without showing a convincing crash.

I added torque after impact to create a visible nosedive before displaying the Game Over state, improving physical feedback and presentation.

What I Learned

  • Rigidbody flight control
  • Input smoothing
  • Collision-state transitions
  • Physics-based visual feedback
  • Basic game-state and UI management
